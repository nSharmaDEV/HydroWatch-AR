### ADEQ semantics finding (new, evidence-backed)

`default.js` line 8 filters with `advisories.filter((advisory) => !advisory.lifted)`. In JS,
`!"N/A"` is false and `!""` is true, so **ADEQ's own current-advisories table excludes every
`N/A` row and includes every blank row**. Consequences:

- The app's existing split (blank → active, `N/A` → `unavailable`/unknown) matches ADEQ's own
  frontend behaviour. It is not a bug to fix; it is behaviour to document.
- `N/A` copy can become checkable: "ADEQ's own current-advisories table does not display this row."
- ADEQ's empty-table text is `No advisories are in effect.` and its failure text is
  `Advisories could not be retrieved.` — the agency itself separates empty from failed, which
  independently validates this app's "failure never yields an all-clear" design.

Per-advisory **reason does not exist** at ADEQ (5 JSON fields; page renders 4 columns). Only ADH
publishes a reason. This is a data gap, not a code gap.
